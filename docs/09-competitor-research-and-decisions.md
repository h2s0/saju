## ADR-023 · 로컬 시제품 기술 구성 (2026-10-27)

이 결정의 단일 상품·시기 상품 제외 범위는 ADR-025가 로컬 체험에 한해 확장했다. 아래는 최초 승인 기록이다.

사용자 승인: Next.js App Router + TypeScript, CSS Modules/CSS 변수, Vitest 단위 검사, Playwright 브라우저 검사. 실제 계산·AI·PG·인증은 연결하지 않는다. 첫 상품은 기질·관계·일·돈 관리 습관·실천 조언이며 올해/월별/대운은 후속으로 분리한다.

공식 근거: [Next.js 설치](https://nextjs.org/docs/app/getting-started/installation), [Vitest 구성](https://nextjs.org/docs/app/guides/testing/vitest), [Playwright 구성](https://nextjs.org/docs/app/guides/testing/playwright), [Vitest 가이드](https://vitest.dev/guide/), [Playwright 설정](https://playwright.dev/docs/test-configuration). 확인일 2026-10-27. Next.js 16.4.3, React 19.3.1, Vitest 5.0.5, Playwright 1.64.1을 선택했고 정확한 의존성 버전은 package-lock.json에 고정한다.

프로젝트 선택: 외부 폰트/아이콘 패키지 없이 시스템 서체와 CSS를 사용한다. src/app의 화면 조립은 서버 컴포넌트, 상호작용·sessionStorage 경계만 클라이언트 컴포넌트로 둔다. 테스트는 비동기 서버 컴포넌트 자체를 Vitest에서 흉내내지 않고 순수 계약·검증에 집중하며 실제 화면은 Playwright로 확인한다. 생성 캐릭터는 승인 상태를 변경하지 않고 로컬 시제품 확인용으로만 사용한다.

## ADR-024 · 시제품의 데이터·구매·풀이 경계 (2026-10-27)

샘플 ID의 확장과 기존 기록 유지 정책은 ADR-025를 따른다. 아래는 최초 저장 경계 기록이다.

사용자 승인 계획에 따라 원시 출생정보를 저장·전송하지 않고 시간 유무에 따른 두 샘플 ID와 모의 구매 상태만 sessionStorage에 둔다. 성별은 수집하지 않는다. 계산·근거 데이터는 `development-fixture`로 표시하며 실제 해석 출처나 정확성을 주장하지 않는다. 990원은 상품 가격안, 실제 체험 청구액은 0원이다.

클라이언트의 샘플 접근 제어는 UI 체험이며 실제 권한 보안이 아니다. 운영 연동 때 서버 계산·인가·주문 원장으로 교체한다. 시간 미상은 시주를 null로 두고 시간 근거를 제외하며, 생년월일 원문 없는 생성 입력과 다섯 영역 JSON 검증을 분리한다. 구조 검증은 정확도 보증이 아니다. [시제품 안내](11-local-prototype.md)와 [풀이 프롬프트 계약](12-reading-prompt-contract.md)에 구현 경계를 기록한다.

## ADR-025 · 7개 상품 체험과 해석 방향 게이지 (2026-10-28)

상태: 사용자 계획 승인 / 로컬 시제품 구현. ADR-023의 첫 단일 상품·시기 상품 제외 범위를 로컬 체험에 한해 확장한다. 실제 유료 판매 범위·최종 가격·연운/대운 계산 연결은 미확정이다.

종합·애정·직업·재물·올해·대운·궁합을 각각 소개·입력·미리보기·모의 구매·고유 상세 결과·보관함으로 연결한다. 상품 ID·다섯 목차·가격안은 [실행 카탈로그](../src/features/products/catalog.ts)가 관리한다. 종합·애정·올해 990원은 가설, 나머지는 가격 미정이고 실제 체험 청구액은 모두 0원이다. 올해는 2026년 예시, 대운은 가상 구간 A·B·C다. 궁합은 두 사람의 독립 입력·시간 미상과 입력 동의를 확인한다.

프로젝트 선택: 5단계 반원은 정비할 때/살펴볼 때/준비할 때/넓혀볼 때/적극 활용할 때라는 해석 방향이다. 점수·확률이 아니며 상품별 고정 fixture로 표시한다. `null` 판단 보류·이유·텍스트 대안을 지원한다. AI에 단계 생성을 맡기지 않는다. 기존 세션 키와 종합 ID를 유지하고 허용 목록으로 새 상품 ID를 정제하여 이전 체험 기록을 보존한다. 이 클라이언트 상태는 실제 구매 권한으로 전환하지 않는다.

기술 / 적용 버전: Next.js 16.4.3 / 브라우저 SVG.
공식 근거: [Next.js page 파일 규약](https://nextjs.org/docs/app/api-reference/file-conventions/page), [MDN SVG path](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Element/path).
확인일: 2026-10-28.
분류: `params`·`searchParams`의 비동기 접근은 공식 API 규약, Server Component 기본 사용은 공식 기본값. 상품 카탈로그 분리·정적 SVG 게이지·중앙 모바일 캔버스 안 상품 배열은 프로젝트 선택이다.
결정과 이유: 서버 페이지에서 라우트 값을 await하고 상품을 검증한다. 기존 SVG 기능으로 반원을 그려 의존성을 추가하지 않고 단계·설명을 접근 가능한 텍스트로 제공한다.
검증: 구현 후 타입·린트·단위·브라우저·빌드 및 모바일 시각 검사 결과를 별도로 기록한다. 이 결정 기록 자체는 검사 통과를 의미하지 않는다.

## ADR-026 · 명리 조사 자료와 실행 규칙을 분리 (2026-10-28)

상태: 사용자 계획 승인 / 조사 자료 준비. [명리 지식 자료](reading-knowledge/)에서 자평명리 중심의 계산 특징·조건·예외·출처·이용 조건·버전·허용 설명·금지 단정을 상품별로 정리한다. 고전 원문과 현대 해설을 구분하고 간여지동·오행/십성의 개수만으로 성격·관계·직업·미래를 확정하지 않는다. 월령·강약·격국·용신·합충형파해 및 원국과 운의 관계는 관점·계산 관례를 명시한다.

자료 출처 확인은 예측 타당성의 입증과 다르다. 조사 규칙은 샘플 fixture와 별개이며 자동으로 운영 코드에 활성화하지 않는다. 필요한 계산 특징·검증 사례·자료 이용 조건이 갖춰진 뒤 후속 평가와 연결을 결정한다. 프롬프트는 계산된 명식과 제공 근거만 사용하며 재계산·미제공 시기 추정·게이지 임의 생성을 금지한다. 실제 공급자·모델·계산 엔진 선정은 이번 결정에 포함하지 않는다.

## ADR-027 · 서체와 하늘 모티프 디자인 시스템 (2026-10-28)

상태: 사용자 요청에 따른 디자인 규칙 확정 / 문서 반영 / UI 적용 전. 커비 공식 포털의 둥근 카드·별 장식과 구름 모티프를 천명록의 하늘·종이·운몽이 세계관에 맞게 해석한다. 수치·컴포넌트 규칙의 단일 기준은 [DESIGN.md](../DESIGN.md), 화면별 적용은 [03 가이드](03-ui-design-system.md)다. ADR-023의 시스템 서체는 기존 구현 기록이며 이번 선택이 후속 디자인 기준을 갱신한다.

선택 이유: 포인트 제목에는 귀여운 인상을, 긴 사주 해설·입력·금액에는 명료한 가독성을 준다. 여러 장식 서체를 혼용하는 대신 두 가족으로 역할을 고정한다. 나눔스퀘어라운드·고운돋움은 조사 후보로 남기며 현재 기본 조합에 포함하지 않는다. 커비의 캐릭터·로고·이미지·소스는 가져오지 않고 자체 별·구름과 기존 운몽이 에셋을 사용한다.

영향: 디자인 토큰·타이포 굵기·카드 반경 기준이 개정되었지만 현재 실행 CSS는 변경하지 않았다. 반원 게이지의 단계·상품별 고유 내용·가격 및 개발용 샘플 고지는 유지한다. 실제 화면의 폰트 로딩·대비·확대·모바일 검사와 시각 검증은 UI 적용 때 수행한다. 문서 검사 결과는 해당 커밋에 별도로 기록한다.
