# 03. 모바일 화면 적용 가이드

2026-10-28 개정. 서체와 둥근 카드·별·구름의 **설계는 확정, 화면 적용은 후속 작업**이다. 색상·서체·크기·간격·컴포넌트·모션·접근성 수치는 루트 [DESIGN.md](../DESIGN.md)에서만 관리한다. 이 문서는 화면별 정보 순서와 적용·검수 안내를 담당한다. 레퍼런스의 관찰과 프로젝트 선택은 [ADR-027](09-competitor-research-and-decisions.md#adr-027--서체와-하늘-모티프-디자인-시스템-2026-10-28)에 구분했다.

## 1. 홈 구성

```text
┌─────────────────────────────┐
│ ☁ 천명록            [내 기록] │
├─────────────────────────────┤
│ 하늘 어딘가에 기록된 이야기…   │ ← 포인트 제목
│       작은 별 · 운몽이         │
│       구름 장식 · 몽실이       │
│      [내 운명록 찾아보기]      │
├─────────────────────────────┤
│ 어떤 이야기가 궁금하세요?      │
│ [   종합 운명록 · 대표 카드   ] │
│ [ 애정 ]          [ 직업 ]    │
│ [ 재물 ]          [ 올해 ]    │
│ [ 대운 ]          [ 궁합 ]    │
│ 각 카드: 범위·가격안·0원 체험   │
├─────────────────────────────┤
│ ① 상품 선택 ② 입력           │
│ ③ 무료 미리보기 ④ 선택 체험    │
│ 개발용 샘플 안내 · 정책        │
├─────────────────────────────┤
│ 홈       오늘 운세      보관함 │
└─────────────────────────────┘
```

- 홈의 감성 제목만 포인트 서체로 표현하고, 상품명·설명·CTA는 기능 서체를 사용한다. 구체적인 가족명과 토큰은 DESIGN.md를 따른다.
- 히어로는 하늘색 배경과 흰 구름, 소수의 별로 구성한다. 캐릭터 아래나 바깥 여백에 장식을 배치하고 눈·손·CTA를 가리지 않는다.
- 대표 종합 카드와 나머지 여섯 상품을 둥근 흰 카드로 구분한다. 작은 화면·큰 글자에서 두 열의 내용이 들어가지 않으면 한 열로 전환한다. PC에서도 모바일 캔버스를 유지한다.
- 상품명·가격·체험 고지를 잘라내거나 말줄임하지 않는다. 미확정 가격은 ‘가격 미정’, 실제 체험 청구액은 0원으로 구분한다. 값과 목차는 [상품 카탈로그](../src/features/products/catalog.ts)를 따른다.
- 홈에서 긴 출생정보 폼을 펼치지 않는다. 상품 소개와 입력으로 연결하고 사용자 자유 질문·상담은 추가하지 않는다.

## 2. 화면별 적용

| 화면 | 카드·서체·장식 적용 | 유지할 핵심 정보 |
| --- | --- | --- |
| 상품 소개 | 포인트 제목, 히어로 구름, 둥근 목차 카드 | 상품별 범위·제한·가격안·0원 체험 |
| 출생 입력 | 기능 서체, 정돈된 흰 카드. 필드 안 별·구름 금지 | 시간 모름·음력/윤달 한계·궁합의 두 입력과 동의 |
| 처리 대기 | 운몽이의 짧은 말풍선과 정적인 구름 | 실제 처리 상태·실패·재시도. 애니메이션을 위해 처리 지연 금지 |
| 무료 미리보기 | 게이지 카드 → 무료 해설 → 목차·체험 CTA | 단계명·이유·샘플 고지. 장식은 게이지 주변 판독 영역 밖 |
| 모의 구매 | 기능 서체와 종이형 요약 카드, 장식 최소화 | 상품·범위·청구액·취소·실제 결제 아님을 명시 |
| 상세 결과 | 게이지 뒤에 크림색 종이 챕터를 한 열로 배치 | 상품별 고유 다섯 영역, 제한과 실천 조언 |
| 보관함 | 둥근 기록 카드, 빈 상태에 운몽이·말풍선 | 기존 결과 열기·중복 구매 방지·초기화·저장 한계 |
| 오늘 운세 | 짧은 응원 카드, 여백의 별 장식 | 고정 개발용 샘플이라는 설명 |

반원 게이지는 DESIGN.md의 해석 방향 규칙을 유지한다. 별 개수·금빛·캐릭터 표정으로 점수나 성공 확률을 추가하지 않는다. 올해·대운의 예시 기간, 궁합의 독립 입력, 개인정보 비저장 정책은 [시제품 안내](11-local-prototype.md)를 따른다.

## 3. 캐릭터와 장식의 분리

운몽이·몽실이의 외형·검수 상태·사용 가능한 에셋은 [캐릭터 가이드](04-character-bible.md)가 기준이다. 검수 대기 사본은 로컬 디자인 확인용으로만 사용하고 이번 문서 개정으로 승인 상태를 바꾸지 않는다. UI 장식은 별·일반 구름만 자체 CSS/SVG로 만들고 캐릭터를 임의로 다시 그리지 않는다. 텍스트와 버튼은 실제 HTML로 렌더링한다.

## 4. 후속 구현과 검수

1. DESIGN.md의 토큰을 기존 `src/styles/globals.css`와 CSS Modules에 매핑한다. 공용 카드의 역할이 실제로 반복될 때만 `src/components/`로 추출한다. 문서의 컴포넌트 목록만 보고 빈 파일을 대량 생성하지 않는다.
2. 선택 서체의 공식 파일 버전·해시·라이선스를 기록하고 자체 호스팅한다. 사용 중인 Next.js 버전의 공식 폰트 가이드를 확인한 뒤 로딩 방식을 적용한다. 폰트 실패 시 시스템 대체 서체로 모든 기능을 사용할 수 있어야 한다.
3. 홈·소개부터 반영하고 입력·결제는 가독성을 우선한다. 게이지·상품 상태·시제품 고지를 보존한다.
4. 지원하는 모든 모바일 폭, 데스크톱 중앙 캔버스, 큰 글자·키보드·포커스·동작 줄이기·폰트 미로딩을 검사한다. 그림자·구름·별로 인한 가로 넘침과 터치 방해, 대비·고지 잘림을 확인한다. 이미지·서체 로딩 전후 레이아웃도 비교한다.
5. 관련 자동 검사와 렌더링 캡처를 확인하고 실제 적용 결과를 기록한다. 현재 문서 정비를 화면 적용·시각 검증 완료로 간주하지 않는다.
