# 11. 로컬 시제품 실행·체험 안내

2026-10-28. 이 문서는 현재 실행 코드의 범위다. 제품 문서의 서버·PG·로그인·운영 정책은 후속 실제 연동 설계이며, 시제품 완료는 실제 풀이 정확성이나 유료 출시 준비 완료를 뜻하지 않는다.

## 실행

Node.js 24.22.1 / npm 11.19.1에서 검증했다. 설치 버전은 [package.json](../package.json)과 [lockfile](../package-lock.json), 공식 선택 근거는 [ADR-023](09-competitor-research-and-decisions.md)을 따른다.

```sh
npm ci
npm run dev
```

개발 서버 기본 주소: `http://127.0.0.1:3000`. 프로덕션 렌더링을 확인하려면 다음을 순서대로 실행한다.

```sh
npm run build
npm run start -- --port 3100
```

```sh
npm run lint
npm run typecheck
npm test
npx playwright install chromium
npm run build
npm run test:e2e
```

Playwright는 3100 포트에서 빌드된 앱을 실행하며 로컬에서는 이미 실행된 서버를 재사용한다. 코드 변경 후에는 빌드와 서버를 갱신해 오래된 앱을 검사하지 않는다. 외부 API 키나 `.env`는 필요하지 않다.

## 디자인 적용 상태

2026-10-28 [DESIGN.md](../DESIGN.md)의 서체·둥근 카드·별·구름을 실행 화면에 적용했다. 홈·상품 소개의 포인트 제목과 브랜드에는 써라운드 에어, 본문·입력·버튼에는 Pretendard를 사용한다. [공식 폰트 출처·버전·라이선스·해시](../src/styles/fonts/README.md)를 보관하고 `next/font/local`로 자체 호스팅한다. 홈·상품 소개의 별·구름은 CSS 장식이며 텍스트·컨트롤과 분리했다. 상품 카드·보관함·오늘 운세·게이지는 공통 카드 토큰, 장문·결제 요약은 종이 카드 토큰을 따른다. 작은 화면에서는 상품 카드를 한 열로 전환하며 큰 글자에서도 가로 넘침 없이 읽도록 한다. 기존 에셋 검수 상태와 샘플 정책은 유지한다. [화면별 가이드](03-ui-design-system.md)에 따라 실제 기기·운영 성능 검수는 별도로 수행한다.

상품 ID는 `basic`, `love`, `career`, `money`, `year`, `decade`, `compatibility`다. 상품·가격안·목차의 실행 기준은 [catalog.ts](../src/features/products/catalog.ts)다. 기존 종합 ID `sample-known`/`sample-unknown`을 유지하며 다른 1인 상품은 `sample-love-known`처럼 상품과 시간 유무를 구분한다. 궁합은 `sample-compatibility-known-known`, `sample-compatibility-known-unknown`, `sample-compatibility-unknown-known`, `sample-compatibility-unknown-unknown` 네 경우다. 입력값에 따른 개인별 결과가 아니라 상품·시간 유무가 같은 입력은 같은 샘플로 합쳐진다.

무료 문구와 상세 본문은 상품마다 구분한 공개 fixture다. 실제 만세력·AI 호출은 없다. 종합·애정·올해 가격안은 990원, 나머지는 **가격 미정**, 모든 체험 청구액은 **0원**이다. 올해는 **2026년 예시**, 대운은 **가상 구간 A·B·C**이며 실제 출생 나이·연운·대운표가 아니다. 월별 운이나 자유 질문·상담은 제공하지 않는다. 상세 본문과 샘플 명식은 공개 코드에 포함된다. 모의 구매 화면은 실제 접근 제어가 아니다.

### 반원 게이지

`정비할 때 → 살펴볼 때 → 준비할 때 → 넓혀볼 때 → 적극 활용할 때`의 다섯 해석 방향이다. 확률·점수·적중률이 아니며 상품별 fixture의 고정 단계·한 줄 요약·이유를 무료/상세에 동일하게 표시한다. 위치·단계명·설명과 스크린리더 텍스트로 색상 외에도 구분한다. 정적 SVG로 동작 줄이기 설정에서도 읽을 수 있다. 계약은 근거 부족 시 `null`인 **판단 보류**를 지원한다. 실제 서비스 단계 산정 규칙은 미확정이며 AI가 단계를 생성하지 않는다.

## 입력·저장 정책

- 성별·이름·연락처·카드·계좌정보는 수집하지 않는다.
- 양력은 형식·실제 날짜·미래 날짜를 확인한다. 음력은 형식과 기본 범위만 확인하며 변환·윤달 존재 여부를 검증하지 않는다.
- 궁합은 각자의 달력·윤달·날짜·시간 모름을 독립적으로 검증하고 상대방 정보 입력 동의를 확인한다. 두 사람의 원문도 저장·전송하지 않는다.
- 시간 모름은 `unknown`으로 유지하고 시주를 `null`로 표시한다. 임의의 시각을 채우지 않는다.
- 출생정보 원문은 폼의 일시적인 값이다. 저장소·URL·분석 이벤트·서버 요청에 넣지 않으며 새로고침 후 입력 복구를 보장하지 않는다.
- `sessionStorage`의 `cheonmyeongrok-demo-v1` 키에 `visited`, `purchased` 허용 목록으로 정제한 샘플 ID 배열만 저장한다. 키를 바꾸지 않아 기존 종합 기록이 유지되며 상품별 구매 상태는 독립적이다. 동일 상품은 시간 앎/모름 조합을 바꿔도 기존 보관 결과를 열며 다시 모의 구매하지 않는다. 같은 탭의 새로고침에서 모의 구매 기록을 복원한다. 탭 종료·브라우저 정책에 따라 사라지며 계정·다른 기기 복원은 없다.
- 저장소를 사용할 수 없으면 메모리에서 체험을 계속하고 복원이 불가능하다는 안내를 표시한다.
- 보관함의 초기화는 확인 후 이 앱의 세션 키만 제거한다. 다른 앱의 저장소는 지우지 않는다.
- 프로토타입 상태는 변조 가능한 클라이언트 데이터다. 향후 주문·권한 마이그레이션의 근거로 쓰지 않는다.

## 재현 순서

1. 홈에서 각 상품 소개를 거쳐 입력 화면으로 이동한다. 궁합에서는 두 사람의 입력·동의를 확인한다. 입력 화면에서 올바른 날짜와 시각을 넣거나 시간 모름을 선택한다. 잘못된 날짜·빈 시간은 필드 오류로 표시된다.
2. `개발용 시나리오`를 열어 일반 처리, 느린 처리(4초), 생성 실패 후 재시도를 선택한다. 실패 화면의 재시도로 무료 샘플을 연다.
3. 무료 결과의 상세 샘플 체험 링크를 누른다. 모의 구매 확인을 선택하고 구매하거나 취소한다. 구매 실패 시나리오를 선택했다면 해제 후 다시 시도한다.
4. 상세 결과의 다섯 영역을 읽고 보관함에서 다시 연다. 새로고침 후에도 동일 샘플이 한 번만 보관되는지 확인한다.
5. 보관함에서 초기화 취소와 확정을 각각 확인한다. 초기화 후에는 상세 결과의 체험 진입 안내가 나타난다.

## 검증 범위와 후속 작업

단위 테스트는 입력 검증, 샘플 계약, 프롬프트의 데이터 최소화·출력 구조·근거 연결, 세션 데이터 정제를 검사한다. 브라우저 테스트는 주요 흐름과 320/360/375/390/414/430px 및 데스크톱 중앙 캔버스를 검사한다. 실제 검사 결과는 커밋의 `Tested` 기록과 작업 완료 보고를 기준으로 한다.

**7개 상품 확장 검증(2026-10-28):** 단위 테스트 98개, 기존 Chromium E2E 19개와 상품 확장 E2E 24개(총 43개), 린트·타입 검사·프로덕션 빌드가 통과했다. 상품별 독립 체험·상품 단위 중복 구매 방지·보관함 복원, 궁합 네 시간 조합·동의·입력 오류, 실패·재시도·취소·초기화, 개인정보 비저장, 게이지 단계·범례·무료/상세 일치를 검사했다. 320/360/375/390/414/430px와 1280px 중앙 캔버스에서 가로 넘침을 확인하고 홈·궁합 입력·무료/상세 화면 캡처를 검토했다. 게이지의 판단 보류는 렌더링 단위 테스트로 확인했다.

**서체·디자인 적용 검증(2026-10-28):** 단위 테스트 98개, Chromium E2E 45개, 린트·타입 검사·프로덕션 빌드가 통과했다. 새 브라우저 검사는 다섯 로컬 폰트 face와 실제 굵기, 외부 폰트 요청 없음, 폰트 차단·200% 글자 확대 시 상품 선택과 입력 진입을 확인한다. 최종 장문·보관함 카드 표면을 맞춘 뒤 빌드와 관련 전체 흐름 캡처 검사 2개를 다시 통과했다. 지원 모바일 여섯 폭과 데스크톱 중앙 캔버스, 홈·상품 소개·입력·게이지·상세·구매·보관함 캡처를 검토했다. 첫 캡처에서 발견한 장식과 글자의 겹침은 장식을 일러스트 영역으로 옮겨 수정했다.
