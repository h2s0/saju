# 11. 로컬 시제품 실행·체험 안내

2026-10-27. 이 문서는 현재 실행 코드의 범위다. 제품 문서의 서버·PG·로그인·운영 정책은 후속 실제 연동 설계이며, 시제품 완료는 실제 풀이 정확성이나 유료 출시 준비 완료를 뜻하지 않는다.

## 실행

Node.js 24.22.1 / npm 11.19.1에서 검증했다. 설치 버전은 [package.json](../package.json)과 [lockfile](../package-lock.json), 공식 선택 근거는 [ADR-023](09-competitor-research-and-decisions.md)을 따른다.

```sh
npm ci
npm run dev
```

개발 서버 기본 주소: `http://127.0.0.1:3000`. 프로덕션 렌더링을 확인하려면 다음을 순서대로 실행한다.

```sh
npm run build
npm run start -- --port 3100
```

```sh
npm run lint
npm run typecheck
npm test
npx playwright install chromium
npm run build
npm run test:e2e
```

Playwright는 3100 포트에서 빌드된 앱을 실행하며 로컬에서는 이미 실행된 서버를 재사용한다. 코드 변경 후에는 빌드와 서버를 갱신해 오래된 앱을 검사하지 않는다. 외부 API 키나 `.env`는 필요하지 않다.

## 화면과 상태

| 경로 | 현재 동작 |
| --- | --- |
| `/` | 상품 범위·가격안과 무료 체험 진입 |
| `/reading/new` | 한국 출생 기준 양력/음력·윤달·날짜·시간 또는 시간 모름 입력 |
| `/reading/processing/[id]` | 일반 지연·느린 처리·생성 실패/재시도 |
| `/reading/preview/[id]` | 샘플 명식, 무료 문단·실천 조언, 상세 목차 |
| `/checkout/[id]` | 0원 모의 구매 확인·취소·실패·재시도 |
| `/readings/[id]` | 기질·관계·일·돈 관리 습관·실천 조언 다섯 영역 |
| `/library` | 모의 구매 샘플 재열람·체험 기록 초기화 |
| `/today` | 날짜·출생정보와 무관한 고정 오늘 운세 샘플 |
| `/support` | 시제품의 데이터·구매 한계 안내 |

`[id]`는 `sample-known` 또는 `sample-unknown`이다. 입력값에 따른 개인별 결과가 아니므로 같은 시간 유무 분기는 같은 샘플로 합쳐진다. 샘플 명식·근거·본문은 공개 코드에 포함되며 모의 구매 조건은 UI 체험용이다. 실제 유료 콘텐츠 접근 제어로 사용하면 안 된다.

무료 문구는 샘플 규칙 ID에 연결된 문장으로 조합한다. 상세 문장은 같은 근거 묶음을 받는 고정 생성기를 통해 반환한다. 실제 만세력·AI 호출은 없다. 올해·월별 흐름과 대운은 제공하지 않는다. 가격안은 990원이며 체험 청구액은 0원이다.

## 입력·저장 정책

- 성별·이름·연락처·카드·계좌정보는 수집하지 않는다.
- 양력은 형식·실제 날짜·미래 날짜를 확인한다. 음력은 형식과 기본 범위만 확인하며 변환·윤달 존재 여부를 검증하지 않는다.
- 시간 모름은 `unknown`으로 유지하고 시주를 `null`로 표시한다. 임의의 시각을 채우지 않는다.
- 출생정보 원문은 폼의 일시적인 값이다. 저장소·URL·분석 이벤트·서버 요청에 넣지 않으며 새로고침 후 입력 복구를 보장하지 않는다.
- `sessionStorage`의 `cheonmyeongrok-demo-v1` 키에 `visited`, `purchased` 샘플 ID 배열만 저장한다. 같은 탭의 새로고침에서 모의 구매 기록을 복원한다. 탭 종료·브라우저 정책에 따라 사라지며 계정·다른 기기 복원은 없다.
- 저장소를 사용할 수 없으면 메모리에서 체험을 계속하고 복원이 불가능하다는 안내를 표시한다.
- 보관함의 초기화는 확인 후 이 앱의 세션 키만 제거한다. 다른 앱의 저장소는 지우지 않는다.
- 프로토타입 상태는 변조 가능한 클라이언트 데이터다. 향후 주문·권한 마이그레이션의 근거로 쓰지 않는다.

## 재현 순서

1. 입력 화면에서 올바른 날짜와 시각을 넣거나 시간 모름을 선택한다. 잘못된 날짜·빈 시간은 필드 오류로 표시된다.
2. `개발용 시나리오`를 열어 일반 처리, 느린 처리(4초), 생성 실패 후 재시도를 선택한다. 실패 화면의 재시도로 무료 샘플을 연다.
3. 무료 결과의 상세 샘플 체험 링크를 누른다. 모의 구매 확인을 선택하고 구매하거나 취소한다. 구매 실패 시나리오를 선택했다면 해제 후 다시 시도한다.
4. 상세 결과의 다섯 영역을 읽고 보관함에서 다시 연다. 새로고침 후에도 동일 샘플이 한 번만 보관되는지 확인한다.
5. 보관함에서 초기화 취소와 확정을 각각 확인한다. 초기화 후에는 상세 결과의 체험 진입 안내가 나타난다.

## 검증 범위와 후속 작업

단위 테스트는 입력 검증, 샘플 계약, 프롬프트의 데이터 최소화·출력 구조·근거 연결, 세션 데이터 정제를 검사한다. 브라우저 테스트는 주요 흐름과 320/360/375/390/414/430px 및 데스크톱 중앙 캔버스를 검사한다. 실제 검사 결과는 커밋의 `Tested` 기록과 작업 완료 보고를 기준으로 한다.

2026-10-27 검증: 단위 테스트 64개, Playwright Chromium E2E 19개, 린트·타입 검사·프로덕션 빌드가 통과했다. 모바일 폭별 가로 넘침과 데스크톱 중앙 캔버스, 키보드 본문 건너뛰기·동작 줄이기 설정을 검사하고 주요 화면 캡처를 확인했다.

실제 iOS/Android 기기 및 VoiceOver/TalkBack 검사는 아직 수행하지 않았다. Chromium 자동화 검사는 이 사용성 검증을 대체하지 않는다. 검수 대기 캐릭터 사본은 로컬 디자인 확인용이며 원본·승인 상태를 바꾸지 않았다. 운영 배포 전에 캐릭터 승인과 실제 기기 검사를 완료해야 한다.
