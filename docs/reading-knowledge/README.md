# 상품별 AI 풀이 지식 팩

확인일 2026-10-28 · 버전 `0.1.0-research` · 자평명리 중심 연구 초안.

이 팩은 **계산된 특징에서 어떤 전통 규칙을 검토하고, 어디까지 설명하며, 언제 판단을 보류할지**를 정한다. 사용자와 자유 상담하는 챗봇 지식이 아니다. 현재 앱의 고정 샘플 계산·해석·게이지에 연결하지 않았다. 파일이 있다는 사실은 실계산, 문장 정확도, 상품 출시 승인을 뜻하지 않는다.

## 파일과 사용 순서

| 파일 | 역할 |
| --- | --- |
| [handbook.md](handbook.md) | 간지·십성·세력·애정·직업·재물·시기 해석을 읽는 개념 사전 |
| [sources.json](sources.json) | 저자·저서·장절·URL·확인일·열람 범위·이용 조건·신뢰 범위 |
| [features.json](features.json) | 계산기가 제공해야 할 최소 특징과 십성 관계명 검토표 |
| [rules.json](rules.json) | 조건·예외·허용 설명·금지 단정·학파·출처를 갖춘 규칙 |
| [tasks.json](tasks.json) | 종합·애정·직업·재물·올해·대운·궁합의 독립 분석 과제 |
| [prompt-contract.md](prompt-contract.md) | 후속 AI 연결을 위한 근거 선별·생성·거부 계약 |
| [cases.json](cases.json) | 누락·반례·정의 충돌을 확인하는 합성 연구 사례 |

1. 실제 계산 엔진이 `features.json`의 특징과 버전·불확실성을 제공한다. 생성 AI는 간지·지장간·대운을 계산하지 않는다.
2. 검토자 또는 후속 규칙기가 상품 과제에 맞는 후보 규칙의 필수 특징·조건·예외를 검사한다. **파일의 규칙을 전부 AI에게 적용시키지 않는다.**
3. 승인된 개별 근거에는 규칙 ID·출처 ID·판정에 쓰인 특징·반례 검토 결과를 묶는다. 격리 규칙은 승인할 수 없다.
4. 생성기는 승인 근거만 받아 설명과 실천 조언을 만든다. JSON 검사와 별도로 근거 충실성을 검토한다.

현재 모든 규칙의 `runtimeEnabled`는 `false`다. 이 팩은 규칙 실행기나 계산 엔진이 아니다. 조건은 사람이 검토할 수 있는 서술이며 실행 가능한 판정식으로 가장하지 않는다.

## 출처 확인과 예측 타당성은 다른 질문이다

원전은 전통에서 무엇을 말했는지 확인하는 1차 자료다. 그 말로 현대 개인의 성격·연애·직업·사건을 정확히 예측할 수 있다는 검증 자료는 아니다. 신분·성별·질병·재난에 관한 고전의 단정과 낙인은 제품에 옮기지 않는다.

이번에 실제 열람한 중심 자료는 다음과 같다. 각 출처의 정확한 장절과 한계는 JSON에 있다.

- [《子平真詮》 판본 안내](https://www.mingsage.com/zh/classics/zi-ping-zhen-quan): 심효첨 원저에 서락오 평주 계통의 내용이 붙은 웹 전사본이다. 사이트의 ‘고적 원구’ 표시만으로 모두 심효첨 원문이라고 확정하지 않는다. 예를 들어 용신의 다섯 취용법은 사이트 자체가 후대 편집 층위라고 밝힌다. 현대 도독·영문 번역을 고전 원문이나 본 프로젝트의 독립 번역으로 표기하지 않았다.
- [《三命通會》 권1](https://zh.wikisource.org/wiki/三命通會_(四庫全書本)/卷01)과 [대운 장](https://www.mastervt.com/books/sanmingtonghui/juan-2/chapter-026): 오행·간지·대운의 전통과 원국을 먼저 검토하는 순서를 확인했다. 웹 전사본의 오탈자와 판본 차이는 영인본 대조가 더 필요하다.
- [이수동의 격국·용신 연구](https://www.kci.go.kr/kciportal/ci/sereArticleSearch/ciSereArtiView.kci?sereArticleSearchBean.artiId=ART002669647): 저자·학술지·DOI와 초록을 확인했다. 연구의 문헌 해석 범위를 참고하며, 전문을 읽은 것으로 표시하지 않는다.
- [김성태의 《육신—어떻게 살 것인가》 공식 도서 소개](https://www.dk-academy.com/book/book_view.jsp?cid=&id=3676): 저자·출판사·ISBN·목차와 소개만 확인했다. 비견~편인의 현대 생활·직업 독법을 대조할 후보이며 목차로 본문 해석을 만들어내지 않는다.

원전 영인본 대조, 이용 가능한 현대 한국어 역주 본문 확보, 학파별 전문가 검토가 남았다. 현대 해설·번역은 저작권이 따로 있으므로 구매·열람과 재배포·학습 허락을 구분한다. 현재 팩에는 장문의 원문·번역·유료 본문을 복제하지 않았다. 표제·전통 관계명·자체 요약을 기록했다.

## 분석의 기본 층위

| 층위 | 확인할 것 | 피할 비약 |
| --- | --- | --- |
| 음양·오행·간지 | 계산 기준과 분포, 일간을 기준으로 한 생극 관계 | 음양으로 성별/성격 확정, 오행 개수로 길흉 판정 |
| 지장간·월령·통근·투간 | 채택 표·절기월·위치와 원국 작용 | 고정 지장간 표와 사령 분일표 혼용 |
| 강약·격국·용신 | 계절·도움·설기·극·구응 및 정의별 후보 | 실령=신약, 부족한 오행=용신, 용신 하나로 전 분야 단정 |
| 합충형파해 | 관계 후보·성립 조건·상충/중재·위치 | 합=결혼, 충=이혼, 형=범죄, 해=배신 |
| 신살 | 계산표와 적용 범위를 밝힌 보조 표식 | 도화·고신·귀인 하나로 사건/인격 단정 |
| 대운·세운·월운 | 선택 관례로 계산한 실제 구간과 원국의 관계 | AI가 기산·교운·월간지를 추정하거나 구간을 사건 날짜로 바꿈 |

십성은 일간과의 관계명이다. 비겁은 ‘나쁜 경쟁자’, 관살은 ‘나쁜 사람’이 아니다. 직업의 책임·학습과 산출·돈 관리 같은 표현은 **프로젝트가 채택한 현대 자기점검 틀**이며 원문이 그 현대 직업이나 습관을 직접 진단했다고 표현하지 않는다. 이런 전환은 규칙의 `basis`에 표시했다.

## 특히 보류한 항목

- **간여지동:** [사주록](https://sajurok.com/column/ganyeojidong-twelve-pillars)은 대표 오행 기준 12개와 본기 비견/겁재 차이를 설명한다. [천을비](https://www.cheoneulbi.com/guide/saju-ganyeojidong-pillar-conflict)는 10개 채택·일주 한정을 주장한다. 이는 합의된 학파 두 개의 확립을 입증하지 않는다. 후자는 제외 이유와 전문가 신원을 충분히 제시하지 않는다. 두 사이트는 충돌 감사 자료이며 판정 권위로 채택하지 않았다. 고전 용례·기명 저자의 정의 대조 전까지 성격·배우자복 해석을 격리한다. 대표 지지 음양과 지장간 본기의 음양도 다를 수 있다.
- **파:** 구체 원전 장절·성립 조건을 독립 대조하지 못했다. 종류를 안다고 가정해서 파혼·파산 해석을 추가하지 않는다.
- **월운·분기 집계:** 절기월 경계·월간지와 별도 규칙이 필요하다. 연간 풀이를 임의로 네 분기에 나누지 않는다. 앱의 가상 분기는 샘플이다.
- **궁합 수치:** 두 차트의 관계 표식에 어떤 가중치를 줄지 승인되지 않았다. 합의 개수로 점수나 결혼 성공 확률을 생성하지 않는다.
- **실제 게이지 산정:** 지식 팩에 단계별 산정식이 없다. 현재 상품 fixture 단계를 실제 사주 근거로 승격하지 않는다. 후속 실서비스는 근거 부족·상충 시 ‘판단 보류’를 허용해야 한다.
- **60갑자 일주별 완결 풀이:** 이번 범위에 없다. 일주 이름만으로 장문의 성격·직업·결혼 서사를 만들어 채우지 않는다.

## 대운과 시기 해석에 필요한 결정

대운은 ‘10년짜리 운’이라는 이름만으로 생성할 수 없다. 순역 기준, 기산에 사용할 절기와 출생 순간의 차이, 환산·반올림, 교운 경계, 시간대/절입/자시 관례, 계산기 버전이 먼저 필요하다. 과거 문헌의 성별 기준을 현재 성별 미수집 입력에 몰래 적용하지 않는다. 관례를 정하지 못하면 계산과 해석을 보류한다.

올해·대운 해석은 원국과 운의 간지 관계, 해당 학파의 용신/격국 검토, 예외를 함께 요구한다. 시간 미상으로 구간이 달라질 수 있으면 계산기가 범위를 반환해야 한다. 이 팩의 AI는 출생 날짜 원문 없이 계산된 구간만 받는다. 월별 데이터가 없을 때 유효한 연간 논점만 설명할 수는 있어도 월별 미래를 채워 넣을 수는 없다.

## 검증과 후속 승인

저장소 루트에서 `python3 scripts/check-reading-knowledge.py`를 실행한다. 검사기는 ID·필드·상태·출처 연결·상품 목록·격리 규칙의 사례 오사용과 필수 반례의 존재를 검사한다. 원격 링크의 장기 가용성, 한문 교감, 조건의 의미적 충족, 생성 문장의 충실성, 사주 예측 정확도를 검사하지 않는다. `cases.json`은 실행 가능한 만세력 정답 세트가 아니라 합성 특징에 대한 검토자의 기대 기준이다.

실제 연결 전에는 (1) 판본·이용 조건, (2) 계산 관례/독립 정답, (3) 규칙의 학파별 조건과 반례, (4) 근거 선별기, (5) 모델별 문장 평가, (6) 단계 산정과 판단 보류를 각각 승인한다. 현재 앱의 [생성 계약](../12-reading-prompt-contract.md)과 실제 타입을 개정할 때 이 연구 계약과 연결하며, 이 문서의 예시를 실행 프롬프트의 이중 원본으로 유지하지 않는다.
