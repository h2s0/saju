# 14. SEO 출시 점검·검색 등록 서식

작성일: **2026-10-28**. 상태: **미실행 서식**. 정책·공식 출처의 단일 기준은 [검색 노출 설계서](13-seo-and-discovery.md)다. 체크박스는 실제 증거를 확인한 뒤 체크한다. 이 파일 작성은 앱 설정·소유 확인·출시 승인이 아니다.

공개 후보는 홈과 실제 출시하는 상품 소개다. 상품별 공개 여부를 기록하며 카탈로그 7개를 일괄 승인하지 않는다. 로컬·미리보기·개인 풀이 페이지는 공개 목록에 넣지 않는다.

## 2. P0 — 검색 공개 전에 확인

- [ ] 실제 운영 콘텐츠·운영자·상품 범위·가격 고지를 검수했다. 샘플을 실제 계산·구매로 표시하지 않는다.
- [ ] 대표 HTTPS 도메인이 정상 응답하며 HTTP/www 정책과 리디렉션이 일치한다.
- [ ] 미리보기·설정 누락 환경은 검색 제외다. `NODE_ENV`만으로 공개되지 않는다.
- [ ] 기본 검색 제외를 유지하고 승인된 공개 페이지만 명시적으로 전환했다.
- [ ] 공개 페이지 HTML의 제목·설명·canonical·OG가 고유하고 개인정보가 없다.
- [ ] robots 메타·검색엔진별 지시·HTTP `X-Robots-Tag` 간 충돌이 없다.
- [ ] 공개 페이지는 크롤링 가능하며 noindex가 없다. 비공개 공개접근 페이지의 noindex는 로봇이 읽을 수 있다.
- [ ] 실제 개인 데이터는 서버 인증·인가로 보호한다. URL을 아는 비인가 사용자가 본문·메타·API로 읽을 수 없다.
- [ ] 입력·처리·미리보기·결제·개인 결과·보관함은 noindex이고 사이트맵에 없다.
- [ ] 사이트맵은 승인된 200 대표 URL만 포함한다. 예시 도메인·개인 ID·추적 쿼리·리디렉션·404가 없다.
- [ ] lastmod는 실제 주요 변경일 또는 생략이며 현재 시각으로 일괄 생성하지 않는다.
- [ ] OG 이미지는 승인된 공용 에셋이고 공유 미리보기에서 정상 표시된다.
- [ ] 구조화 데이터가 있다면 본문과 일치하고 허위 가격·리뷰·효능이 없으며 도구로 검사했다.
- [ ] HTML에 실제 제목·본문·링크가 있고 잘못된 상품은 올바른 오류 상태를 반환한다.
- [ ] 캐시·빌드 전후 환경 변경 반영을 확인했다. 미리보기 주소가 canonical/사이트맵에 섞이지 않는다.
- [ ] 320~430px·키보드·모바일 로딩을 확인하고 성능 측정 결과와 후속 조치를 기록했다.

아래는 **예정 검사**다. 현재 앱의 통과 기록이 아니다. 개인 데이터 검사는 가짜 입력을 이용한 로컬/통제된 환경에서 수행한다.

| --- | --- | --- |

| 운영 승인 홈/상품 | 200·고유 메타·자기 canonical·검색 허용 | 미실행 |

단위 검사로 공개 정책·URL 생성·사이트맵 필터를 확인하고, 브라우저/HTTP 검사로 최종 메타데이터·헤더·상태·렌더링을 확인한다. 일반 사용자와 로봇에게 다른 상품 주장을 제공하지 않는다. 검사 결과에는 커밋·환경·날짜·명령·요약을 남긴다. 프로젝트에 존재하는 타입·린트·빌드 명령도 실행하되 실제 색인 여부와 구분한다.

## 4. 검색 콘솔 등록 기록

아래 절차는 도메인·계정 권한과 공개 배포가 준비된 뒤 실행한다. 비밀번호·API 키·로그인 세션·개인 URL을 이 문서에 적지 않는다.

### Google Search Console

1. 운영 계정으로 속성을 만든다. DNS 권한이 있으면 도메인 속성을 검토하고, 범위를 제한해야 하면 URL 접두어 속성과 지원되는 확인 방식을 선택한다.
2. 콘솔이 발급한 DNS 레코드 등으로 소유 확인한다. DNS 방식은 콘솔·도메인 공급자의 실제 안내를 따른다. 확인에 사용한 레코드를 임의로 지우지 않는다.
3. 운영 사이트맵을 제출하고 처리 결과를 확인한다.
4. 승인된 공개 홈·상품 URL을 검사한다. 등록된 버전·실시간 검사·선택된 canonical을 구분해 기록하고 필요하면 색인 요청한다. 요청이 노출을 보장하지 않는다.

공식: [소유권 확인](https://support.google.com/webmasters/answer/9008080), [URL 검사](https://support.google.com/webmasters/answer/9012289).

### 네이버 Search Advisor

1. 운영 호스트를 웹마스터 도구에 등록한다.
2. 안내된 HTML 메타 태그 또는 파일 업로드로 소유 확인한다. 메타 방식은 Next.js 서버 메타데이터에 반영하고 HTML 출력을 확인한다.
3. `요청 → 사이트맵 제출`에서 운영 사이트맵을 제출하고 수집·색인 상태를 관찰한다. 모든 URL의 수집·노출이 보장되지는 않는다.

공식: [시작 안내](https://searchadvisor.naver.com/guide/seo-basic-intro), [사이트맵 제출](https://searchadvisor.naver.com/guide/request-feed).

### Bing Webmaster Tools

1. 운영 사이트를 추가하고 파일·메타 태그·DNS 등 지원 방식으로 확인한다. Google Search Console 가져오기는 해당 권한 승인 후 선택할 수 있다.
2. 운영 사이트맵을 제출하고 처리 상태·발견 URL을 확인한다. 실제 콘솔에서 제공하는 절차를 재확인한다.

공식: [소유 확인](https://www.bing.com/webmasters/help/add-and-verify-site-12184f8b), [사이트맵 제출](https://www.bing.com/webmasters/help/sitemaps-3b5cf6ed). 조사 시 Bing 본문은 공식 검색 추출로 확인했으므로 실제 화면 검증은 아직 남아 있다.

| 서비스 | 속성·호스트 / 담당 | 소유 확인일·방식 | 사이트맵 제출·처리 결과 | 공개 URL 검사 결과 |
| --- | --- | --- | --- | --- |
| Google | 미정 | 미실행 | 미실행 | 미실행 |
| 네이버 | 미정 | 미실행 | 미실행 | 미실행 |
| Bing | 미정 | 미실행 | 미실행 | 미실행 |

외부 검사·공유 디버거에 개인 결과 URL·공유 토큰·출생정보를 보내지 않는다. 소유 확인용 공개 토큰과 비밀 자격증명을 구분하며 계정 권한 자체를 코드에 저장하지 않는다.

## 5. 공개 후 관찰·이상 대응

출시 직후와 초기 한 달 동안 매주 확인하는 것을 프로젝트 기본 운영안으로 삼고 담당자·주기는 출시 때 확정한다.

- [ ] 사이트맵 처리·페이지 색인 제외 사유·대표 URL·404/서버 오류를 확인했다.
- [ ] 검색 노출·클릭·검색어·클릭률을 기록했다. 사이트 방문 분석 도입은 개인정보·동의 정책과 별도로 결정한다.
- [ ] 실사용 성능을 확인했다. 데이터 부족 상태를 성능 통과로 기록하지 않는다.
- [ ] 신규 상품·도메인·리디렉션·메타데이터 변경 뒤 회귀 검사를 반복했다.
- [ ] 개인 페이지 노출 여부를 확인했다. 문제가 있으면 담당자에게 연결하고 실제 데이터 접근부터 보호한 뒤 노출·메타데이터·크롤링 정책을 바로잡는다.

| --- | --- | --- | --- | --- |
| 미실행 | 미정 | — | — | — |

검색 공개 완료 기록: **미완료**. 필요한 선행 결정은 대표 도메인·배포 환경·공개 상품·운영 담당자다. 문서 작성만으로 실제 서비스 출시 조건이 충족되지는 않는다.
